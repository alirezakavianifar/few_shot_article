# **FSAKE: Few-shot graph learning via adaptive neighbor class knowledge embedding**

Published in *Expert Systems With Applications* (2025)

---

# 1. Problem Background

## Few-Shot Learning (FSL)

Few-shot learning aims to classify new categories using only a small number of labeled examples (e.g., 1-shot or 5-shot per class). Traditional deep learning requires large datasets, which are often unavailable in real-world applications.

Existing FSL approaches fall into two main categories:

### (1) Meta-learning based methods

* Optimization-based (e.g., MAML-style)
* Metric-based (e.g., Prototypical Networks)

These methods focus mainly on **task-level relationships**, but often ignore fine-grained **relationships among samples within the task**.

### (2) Graph Neural Network (GNN)-based methods

These methods model samples as nodes in a graph and exploit relationships among support and query samples.

GNN-based FSL methods include:

* Node-level methods
* Edge-level methods
* Graph-level methods (most relevant here)

Graph-level FSL uses pooling to compress instance-level nodes into **class-level knowledge representations**.

---

# 2. Key Limitation in Existing Graph-Level FSL

Most existing graph-level approaches:

* Evaluate node importance using only **intrinsic node features**
* Ignore **neighbor class information**
* Risk propagating incorrect class knowledge during hierarchical pooling/unpooling

### Why is this problematic?

1. **Inter-class issue**:
   Easily distinguishable samples may be selected, but these are not the most informative ones.
2. **Intra-class issue**:
   Shortcut features (e.g., common patterns like "hands") may dominate node selection.
3. **Error accumulation**:
   Incorrect class knowledge propagates through pooling layers, worsening performance.

---

# 3. Proposed Solution: FSAKE

The authors propose:

## **FSAKE (Few-Shot Adaptive neighbor class Knowledge Embedding)**

It introduces two key components:

---

# 4. Component 1: Knowledge Filtering (KF)

### Purpose:

Select more representative and informative class knowledge during graph pooling.

### Core Idea:

Instead of evaluating nodes using only their own features, FSAKE:

* Aggregates **first-order neighbor information**
* Uses both **structure + feature information**
* Computes node importance via a GCN-based scoring mechanism

### Improvements:

* Preserves **inter-class difficult samples**
* Preserves **intra-class representative samples**
* Avoids selecting trivial or shortcut samples

### Node Selection Strategy:

* **1-shot task** → Use absolute top-k scores
* **5-shot task** → Select nodes closest to class centroid

### Effect:

More accurate and meaningful class knowledge extraction.

---

# 5. Component 2: Knowledge Correction (KC)

### Motivation:

Pooling introduces hierarchical transformations. Incorrect knowledge propagation may accumulate errors.

### Solution:

Add an additional **correction loss** at the penultimate layer.

Total loss:

[
L = L_{classification} + \lambda L_{correction}
]

Where:

* Classification loss = final layer cross-entropy
* Correction loss = cross-entropy at penultimate layer
* λ = balancing coefficient

### Effect:

* Supervises intermediate representations
* Reduces incorrect inter-layer propagation
* Stabilizes learning

# 6. Detailed Implementation & Architecture

Here’s a **clear breakdown of how the FSAKE model is actually implemented**, based on the paper—focusing on architecture, training pipeline, and key design choices.

---

## 6.1. Overall implementation pipeline

FSAKE follows a **Graph U-Net–style architecture** with two phases:

### 🔹 Encoder (Downsampling)
* Graph construction
* Graph reasoning (GNN layers)
* **Graph pooling (Knowledge Filtering, KF)**

### 🔹 Decoder (Upsampling)
* Graph unpooling
* Graph reasoning
* **Correction loss (Knowledge Correction, KC)**

---

## 6.2. Input and feature extraction

### 📥 Input:
Each few-shot task consists of:
* **Support set**: labeled examples (N-way K-shot)
* **Query set**: unlabeled examples

### ⚙️ Feature extractor:
* A simple CNN: **4CONV**
* Output: **128-dimensional feature vector per image**

### 🧠 Node representation:
Each sample becomes a graph node:
* Feature vector (128-dim)
* label encoding:
  - Support: one-hot vector
  - Query: uniform distribution

👉 Final node dimension: **133-dimensional vector**

---

## 6.3. Graph construction

### Adjacency matrix initialization:
* If same class (support nodes): **1**
* Different class: **0**
* Query-related edges: **0.5**

👉 This creates an initial graph connecting all samples.

---

## 6.4. Graph reasoning (GNN layers)

Each layer updates node features using:
* Neighbor aggregation
* Learned adjacency matrix

Key idea:
* Combine:
  * **Low-level relationships (original graph)**
  * **High-level relationships (learned via MLP)**

👉 Output:
* Updated node features
* Refined adjacency matrix

---

## 6.5. Knowledge Filtering (KF) – Graph pooling

This is the **main innovation in implementation**.

### Step 1: Compute node importance score
Instead of only using node features (like older methods), FSAKE uses:
* Node features
* **Neighbor information**
Using a GCN-like operation:
* Produces a score between **0 and 1**

### Step 2: Node selection
Different strategies depending on task:
* 🔹 **1-shot**: Select nodes with **highest scores (Max strategy)**
* 🔹 **5-shot**: Select nodes **closest to class centroid (Nearest strategy)**

### Step 3: Pooling operation
* Keep:
  * All **query nodes**
  * Selected **support nodes**
* Remove less important nodes
* Multiply node features by their scores to emphasize important nodes.

👉 Result:
* Smaller graph
* More informative nodes

---

## 6.6. Graph Unpooling (Decoder)

Reconstruct original graph:
* Restore nodes to original positions
* Use **skip connections** (like U-Net)
* Fill missing features using graph reasoning

---

## 6.7. Knowledge Correction (KC)

### Why needed?
Pooling can introduce errors → wrong knowledge propagation.

### Implementation:
* Add **extra loss at the penultimate layer**
* Use **cross-entropy loss** twice:
  1. **Final classification loss**: From last layer
  2. **Correction loss**: From second-to-last layer

### Final loss:
[ L = L_1 + \lambda L_2 ]
* \(L_1\): final classification loss
* \(L_2\): correction loss
* \(\lambda\): balancing parameter

👉 This enforces better intermediate representations and reduces error accumulation.

---

## 6.8. Training setup

### Optimizer:
* **Adam**
* Learning rate: **1e-3**
* Weight decay: **1e-6**

### Training strategy:
* Episodic training (standard in few-shot learning)
* Each batch = one task

### Evaluation:
* **500 random tasks**
* Report: mean accuracy and **95% confidence interval**

---

## 6.9. Architecture details

* Feature extractor: 4-layer CNN
* Graph layers: Multiple pooling + unpooling layers
* Best configuration: **2 pooling layers**

👉 Why?
* Too many → overfitting
* Too few → weak representation

---

## 6.10. Important implementation choices

* ✅ **Keep all query nodes**: Only support nodes are pooled; ensures predictions remain stable.
* ✅ **Adaptive node selection**: Different strategies for 1-shot vs 5-shot.
* ✅ **Learnable adjacency matrix**: Not fixed → dynamically updated.
* ✅ **Skip connections**: Preserve original information.

---

## 6.11. Summary (implementation in one flow)

1. Extract features using CNN
2. Build graph (nodes + adjacency)
3. Run GNN reasoning
4. Compute node importance (with neighbors)
5. Pool graph (keep best nodes)
6. Repeat pooling layers
7. Unpool graph (restore structure)
8. Apply correction loss + classification loss
9. Update model via backprop

---

## 6.12. Intuition

Implementation-wise, FSAKE improves over earlier models by:
* Making **node selection smarter (KF)**
* Making **training more stable (KC)**
* Using a **U-Net-like graph architecture**

---

# 7. Theoretical Contributions

Compared to prior graph-level FSL methods:

| Aspect          | Existing Methods   | FSAKE                        |
| --------------- | ------------------ | ---------------------------- |
| Node importance | Node features only | Node + neighbor class info   |
| Pooling         | Feature-driven     | Structure-feature integrated |
| Error control   | None               | Correction loss              |
| Adaptivity      | Limited            | Task-adaptive                |

FSAKE can degenerate to traditional node-level GNN if pooling is disabled.

# 9. Results and Numbers Analysis

Here’s a clear explanation of the **results and numbers reported in the paper**, focusing on what they mean and why they matter.

---

## 9.1. What the reported numbers represent

The paper evaluates a model called **FSAKE** on *few-shot classification tasks*.

### Key setup:

* **5-way 1-shot** → classify among 5 classes with **only 1 labeled example per class**
* **5-way 5-shot** → same, but with 5 examples per class
* Metric: **accuracy (%)**, with **95% confidence intervals**

👉 So when you see something like:

* `61.86 ± 0.72%`
  it means:
* Average accuracy = **61.86%**
* Uncertainty ≈ ±0.72%

---

## 9.2. Main results (core numbers)

### ✅ On miniImageNet

* **FSAKE:**
  * 1-shot: **61.86%**
  * 5-shot: **79.66%**

#### Comparison:
* Best baseline (HGNN):
  * 60.91% → 77.54%

👉 Improvement:
* **+0.95% (1-shot)**
* **+2.12% (5-shot)**

✔ Interpretation:
Even small gains (~1–2%) are significant in few-shot learning.

---

### ✅ On CUB-200-2011 (fine-grained dataset)

* **FSAKE:**
  * 1-shot: **77.00%**
  * 5-shot: **89.66%**

#### Baseline (HGNN):
* 75.64% → 89.19%

👉 Improvement:
* **+1.36% (1-shot)**
* **+0.47% (5-shot)**

✔ Interpretation:
* Gains are smaller in 5-shot because more data already helps all models.
* Still strong improvement in harder **1-shot** case.

---

### ✅ On tieredImageNet

* **FSAKE:**
  * 1-shot: **65.27%**
  * 5-shot: **83.33%**

#### Baseline:
* 63.95% → 82.84%

👉 Improvement:
* **+1.32% (1-shot)**
* **+0.49% (5-shot)**

✔ Interpretation:
* Consistent improvement across datasets → good generalization.

---

### ✅ On CIFAR-FS

* **FSAKE:**
  * 1-shot: **69.78%**
  * 5-shot: **85.92%**

#### Baseline:
* 67.67% → 86.16%

👉 Result:
* **+2.11% (1-shot)** ✅
* **−0.24% (5-shot)** ❌ slight drop

✔ Interpretation:
* Works very well when data is scarce (1-shot)
* Slight degradation when data is sufficient (5-shot)

---

## 9.3. Key takeaways from the numbers

### 1. Strongest gains in 1-shot setting
Across all datasets:
* Improvements are **larger in 1-shot than 5-shot**

👉 Why?
Because FSAKE is designed to:
* Better use **neighbor information**
* Extract **useful class knowledge** from very limited data

---

### 2. Consistent improvements over baseline
Compared to HGNN:
* Always better or very close
* Gains typically:
  * **~1–2% (1-shot)**
  * **~0.5–2% (5-shot)**

👉 This consistency is important in ML research.

---

### 3. Big gains vs older methods
Example (miniImageNet):

👉 That’s **~8.7% improvement**, which is large.

### 4. Graph-based methods outperform non-graph ones
The paper shows:
* Graph models > non-graph models

Example:

  * +8–10% improvement

👉 Reason:
Graphs model **relationships between samples**, not just features.

Adds **two major improvements**:

#### 1. Knowledge Filtering (KF)
* Node importance =
  **node features + neighbor class information**

  * **hard samples (inter-class)**

#### 2. Knowledge Correction (KC)

### ✅ Better node selection
HGNN:
* “This node looks important individually”

### ✅ Handles difficult samples
* FSAKE prioritizes **hard-to-classify samples**
* HGNN may focus on **obvious ones**

### ✅ Prevents error propagation

* FSAKE: correction loss reduces this

# 13. Overall Significance

This paper advances graph-based few-shot learning by:

* Moving from *self-feature-based pooling*
  → to *neighbor-informed adaptive pooling*
* Introducing hierarchical supervision
  → to stabilize class knowledge propagation

It strengthens the reliability of graph-level FSL and demonstrates that:

> Class knowledge should not be evaluated independently —
> it must be understood relationally.
